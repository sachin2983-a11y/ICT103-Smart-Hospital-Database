# ICT103 Smart Hospital Management System

## Assessment 3 – Database Systems

This repository contains the SQL work completed for the ICT103 Database Systems Assessment 3 project: **Smart Hospital Management System**.

The database was designed and implemented using **MySQL** and managed through **DBeaver**. The project demonstrates the conversion of an ERD/EERD design into a relational database with primary keys, foreign keys, constraints, sample data, and SQL queries.

## Database Structure

The database contains the following eight tables:

1. Department
2. Employee
3. Doctor
4. Nurse
5. Administrative_Staff
6. Patient
7. Appointment
8. Billing

The Employee entity is used as the supertype for Doctor, Nurse, and Administrative Staff. The specialization follows a **total and disjoint** structure in the database design.

## SQL Files

- **main_script.sql** – contains the main database and table creation statements.
- **Script-3.sql** – contains additional SQL used during database implementation and data population.
- **Query_Script.sql** – contains the five required SQL queries used to test and analyse the database.

## Required Queries

The project includes SQL queries to:

1. Display all doctors together with their department names.
2. Identify patients who have attended more than one appointment.
3. Calculate the total billing amount generated by each department.
4. Find the doctor with the highest consultation fee.
5. Display doctors ordered by specialization and consultation fee.

## Database Design Features

The implementation includes:

- Primary keys for unique record identification
- Foreign keys for relationships between tables
- Referential integrity between related records
- UNIQUE and NOT NULL constraints where appropriate
- Sample data for testing the database
- JOIN, GROUP BY, HAVING, SUM(), MAX(), and ORDER BY queries

## Software Used

- MySQL 8.0
- DBeaver Community Edition

## Purpose of This Repository

This repository provides the SQL scripts used for the ICT103 Assessment 3 database implementation so that the database structure and required queries can be reviewed independently. A DBeaver project export may also be provided separately for further inspection of the database workspace.
